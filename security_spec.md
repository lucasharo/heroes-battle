# Security Specification — Thetan Arena Auth & Ranking

## 1. Data Invariants
1. **PII Isolation**: `/users/{userId}` stores the user's private `email`. Only `request.auth.uid == userId` may `get`, `create`, or `update` `/users/{userId}`. Listing `/users` is strictly denied (`allow list: if false`).
2. **Zero-PII Leaderboard**: `/rankings/{userId}` contains ONLY public arena gameplay fields (`uid`, `displayName`, `heroId`, `trophies`, `wins`, `matches`, `kills`, `createdAt`, `updatedAt`). Shadow fields (`email`, `isAdmin`, `role`) are rejected by `keys().hasOnly(...)`.
3. **Identity Integrity**: On every write to `/users/{userId}` or `/rankings/{userId}`, `incoming().uid == request.auth.uid` and `userId == request.auth.uid`. `uid` and `createdAt` are immutable across updates.
4. **Temporal Integrity**: `createdAt == request.time` on creation and `updatedAt == request.time` on both creation and update.
5. **Progression Bounds**: On initial creation, `trophies == 0`, `wins == 0`, `matches == 0`, `kills == 0`. On match updates, `trophies` increment is capped at `+80` per update, `matches` increment is capped at `+1`, `wins` increment is capped at `+1`, and `kills` increment is capped at `+40`.
6. **Daily Quests & Wallet Isolation**: `/users/{userId}/progression/wallet` and `/users/{userId}/dailyQuests/{dateKey}` require the parent `/users/{userId}` document to exist (Master Gate), are strictly restricted to `request.auth.uid == userId`, forbid `list` enumeration, require exact 3-element `quests` lists, validate `dateKey` / `lastLoginDateKey` (`YYYY-MM-DD`), enforce `loginStreak` bounds (`<= 1` increment or reset to `1`, no increment without date change), and bound `xp`/`gems` increments (`+1000 XP`, `+560 Gemas` per update).
7. **ID Poisoning Guard**: Every single-doc operation validates `isValidId(userId)` (`^[a-zA-Z0-9_-]+$`, `<= 128` chars) and every string has strict `.size()` bounds.
8. **Match History Isolation & Immutability**: `/users/{userId}/matches/{matchId}` requires the parent `/users/{userId}` document on `get` and `create`, binds `uid == request.auth.uid == userId`, validates `victory` (`bool`), `heroId`, `mode` (`royale`, `brawl`, `superstar`, `tower`), bounded stats (`kills` `0..40`, `placement` `1..8`, `trophyDelta` `-80..80`, `playedAtMs` >= 0), enforces `createdAt == request.time`, restricts `list` queries to `request.auth.uid == userId` with `request.query.limit <= 20`, and denies all updates and deletes.
9. **Hero Mastery Integrity & Atomic Gem Frame Evolution**: `/users/{userId}/heroMastery/{heroId}` binds `uid == request.auth.uid == userId`, validates `heroId` against the 21 playable heroes (`heroId` matches document path), bounds `matches` (`+1` max per match update), `kills` (`+40` max per match update), and optional `bonusPoints` (`0..100000`, upgradable atomically only when paired with a `writeBatch` deducting `>= 25` Gems from `progression/wallet`), validates `equippedFrame` against the 7 allowed frame preferences, enforces mastery point unlock thresholds (`matches * 40 + kills * 15 + bonusPoints`) before equipping higher cosmetic frames, and bounds `list` queries to `request.query.limit <= 30` with `resource.data.uid == request.auth.uid`.
10. **Hero Skin Integrity**: `/users/{userId}/heroSkins/{heroId}` binds `uid == request.auth.uid == userId` with Master Gate (`exists(/users/{userId})`), validates `heroId` against the 21 playable heroes (`heroId` matches document path), restricts `equippedSkin` to `['classic', 'chroma', 'solar', 'eclipse', 'vanguard', 'infernal', 'celestial']`, enforces Hero Mastery unlock thresholds for mastery skins (`solar` >= 60 pts, `eclipse` >= 180 pts) and Battle Pass `unlockedCosmetics` membership for seasonal skins (`vanguard`, `infernal`, `celestial`), bounds `list` queries to `request.query.limit <= 30` with `resource.data.uid == request.auth.uid`, and denies deletes.
11. **Battle Pass Integrity & Atomic Elite Purchase**: `/users/{userId}/battlePass/{seasonId}` (`seasonId == 'season1'`) binds `uid == request.auth.uid == userId` with Master Gate (`exists(/users/{userId})`), forbids `list` enumeration and deletes, enforces bounded seasonal XP deltas (`+400` max per write), requires `premiumUnlocked == false` on create, and uses `getAfter()`/`get()` cross-document atomicity on `progression/wallet` (`gems - 250`) when activating `premiumUnlocked = true`.
12. **Hero Evolution Integrity & Atomic Gem Deduction**: `/users/{userId}/heroEvolutions/{heroId}` binds `uid == request.auth.uid == userId` with Master Gate (`exists(/users/{userId})`), validates `heroId` against the 21 playable heroes (`heroId` matches document ID), bounds `level` strictly to integers `2..5`, allows `create` only at `level == 2` and `update` only by `+1` step per write, and enforces atomic Gem deduction against `progression/wallet` (`get` + `getAfter` verifying wallet balance decreased by at least the exact evolution tier cost `25/45/75/110`).
13. **One-Time Account Gift Redemption Atomicity**: `/users/{userId}/redemptions/{giftId}` (`giftId == 'season1_welcome_10k'`) binds `uid == request.auth.uid == userId` with Master Gate (`exists(/users/{userId})`), enforces `gemsGranted == 10000`, forbids listing, updates, and deletes (`allow list, update, delete: if false`), and uses cross-document `exists`/`existsAfter`/`get`/`getAfter` atomicity with `progression/wallet` (`gems == existing().gems + 10000`) so the welcome pack can only ever be credited once per authenticated account.

## 2. "Dirty Dozen" Adversarial Payloads
1. **Unauthenticated write to `/rankings/attacker`**: `{ uid: "attacker", displayName: "Hack", ... }` -> DENIED (`isSignedIn()`).
2. **Cross-user write to `/rankings/victim` by `attacker`**: `request.auth.uid == "attacker"` -> DENIED (`uid == request.auth.uid`).
3. **Cross-user PII read of `/users/victim` by `attacker`**: `get /users/victim` -> DENIED (`request.auth.uid == userId`).
4. **Users collection enumeration**: `list /users` -> DENIED (implicit + explicit deny).
5. **Shadow/Ghost Field Injection**: `{ ..., role: "admin" }` or `{ ..., isVerified: true }` -> DENIED (`keys().hasOnly(...)` / `affectedKeys().hasOnly(...)`).
6. **PII Leak in Leaderboard**: Adding `"email": "x@y.com"` to `/rankings/{userId}` -> DENIED (`keys().hasOnly(...)`).
7. **Trophy Spoofing on Create**: Creating `/rankings/{uid}` with `trophies: 99999` -> DENIED (`trophies == 0` on create).
8. **Trophy Spike Cheat on Update**: Updating `/rankings/{uid}` from `30` to `5000` trophies in a single match -> DENIED (`trophies <= existing().trophies + 80`).
9. **Spoofed Client Timestamp**: `updatedAt: Timestamp.fromMillis(0)` instead of `serverTimestamp()` -> DENIED (`updatedAt == request.time`).
10. **Immutable Field Mutation**: Changing `createdAt` or `uid` on update -> DENIED (`incoming().uid == existing().uid && incoming().createdAt == existing().createdAt`).
11. **Oversized String / Resource Exhaustion**: `displayName` with 500 characters or `heroId` > 24 chars -> DENIED (`size()` bounds).
12. **Malformed Document ID / Wallet Spike**: Path `/rankings/..bad$id` or inflating `gems` by `999999` in `/users/{uid}/progression/wallet` -> DENIED (`isValidId` and bounded wallet increments).
